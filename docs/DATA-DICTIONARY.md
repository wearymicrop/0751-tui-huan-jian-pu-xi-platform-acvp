# 数据字典

## 输入

| 字段 | 用途 |
|---|---|
| `as_of` | 盘点时刻。晚于它的动作列入待生效 |
| `default_batch` | 归档请求未指定批号时使用 |
| `parts` | `serial`、`batch`、`kind`、`registered`，登记时间用于确定件数与事件是否有效 |
| `aliases` | `alias`、`serial`，别名须映射到登记的规范序列号 |
| `returns` | `ticket`、`serial`、`action`、`at`，动作取 `return` 或 `restock` |
| `events` | `child`、`parent`、`action`、`revision`、`at`，动作取 `mount` 或 `detach`，序号为每个子件的正整数 |

编码按字符串归一全半角、两端空格和大小写。保留前导零。同票号或同序列件档案采用首次输入记录，留存其余冲突行。别名歧义被隔离，规范号始终可直接使用。文件中数组下标从 1 起计为来源行。

## 时间与状态

入库和拆装时间须含显式时区，统一归一到 UTC。拆装序号按子件校验，同一时刻先按序号筛选，再按拆出、退回、复入库、装入分阶段回放。同阶段按源行裁决。时间窗 `[start, end)` 包含起点，排除终点；查询终点默认是盘点时刻。拆装边保留关闭前的历史。回溯时逐边取交集，有效历史反向装配可以存在，同一时刻成环则拒绝。

盘点件数取已登记的唯一序列号，归属按争议、在装、退回、库存依次判定。冲突动作不改变有效边，争议状态仍保留此前已采信的父件。异时过期序号单独隔离。退回要求先解除该部件与父件、子件的装配关系。档案自身的批号有歧义时，召回结果在 `excluded_origins` 列出按首条记录匹配的争议起点。

## 处置下发

`dispatch` 请求接受 `source`（或 `sample`）、`batch`、`start`、`end`。首次下发不改变源数据；同一批号与时间窗只对应一条下发批次，重跑返回同一结果。

`/api/dispatches/{id}/supplements` 接受一份只含 `parts`、`aliases`、`returns`、`events` 中若干数组的补录数据（可选带更晚的 `as_of`）。补录按原顺序追加，完全相同的行被忽略，相同补录只记账一次。每次补录都基于「初始数据 + 全部已补录数据」重算全量影响。

每件任务包含：`task_id`（只由处置内容决定）、`serial`、`action`（`teardown_quarantine` 现场拆出、`inspect_quarantine` 核查隔离、`hold_review` 争议复核）、`lane`（现场 / 库房 / 待判）、`priority`、`state`、`active_parent`、`reason_codes`、`exposures`，以及 `basis`：下发批次、修订号、查询窗、源数据摘要、规则版本和本条任务的暴露源行。

每份 `basis` 单独可复核。修订按 `seq` 追加保存；`delta` 按任务号比较相邻两版，列出 `retained`（保留）、`withdrawn`（撤回）、`added`（新增）。撤回任务的旧记录仍可按修订号取回。落库失败时旧修订保持有效，作业登记为 `failed`，可用 `/jobs/{job_id}/retry` 续跑。

## 输出与归档

`mount_rows` 按由子到父的顺序列出构成暴露窗的装入源行。证据查询还列出有效边的拆出行、动作、当前位置及关联异常。归档对原始输入、规范化查询、规则版本和实算结果生成 SHA-256，同摘要提供同一 ID。此归档用来比对重算差异，记录登录人员或审批信息的流程由售后台账负责。
